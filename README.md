# 叙境 · AI 小说创作工作台

Windows 本地 AI 小说创作工作台。作品保存在本机，通过自定义 Responses 模型完成构思、双线大纲、角色代入、场景正文和读者评审。

## 启动

需要 Node.js 24 或以上。首次获取源码后运行：

```powershell
npm install
npm run dev
```

开发命令自动编译主进程、启动本机 Vite 界面并打开 Electron 桌面窗口。界面修改自动刷新；修改主进程后关闭窗口并重新启动。端口 5173 仅供开发工具使用。

Electron 第一次启动会下载运行时。如果 GitHub 下载无法连通，可在当前 PowerShell 中执行下列命令安装同一版本；安装器仍校验软件包内置的 SHA-256：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
node node_modules/electron/install.js
```

也可先构建，再运行无需开发服务的桌面版本：

```powershell
npm run build
npm start
```

## 创作流程

1. 点击「新建作品」，填写作品名称；在「作品概览」描述题材、读者与故事方向。「发散故事构思」会唤出创作伙伴，先追问再发散。
2. 在「构思」的「灵感画布 / 人物与设定」中整理素材。选中便笺或分组，使用「完善选中灵感」或「根据分组素材编排大纲」准备 AI 任务。
3. 在「情节规划」查看「世界因果 / 叙述顺序」。世界图连线建立因果；叙述图只展示阅读顺序。拖动仅调整布局，章节与场景排序在写作目录中操作，跨章移动在场景详情中明确选择。

   画布与两张图的工具栏提供「整理」（快捷键 `L`）：灵感画布可自动整理全部（分组内收紧排列、整体按阅读顺序排成网格）、按关联聚类或只整理选中卡片；世界因果可按因果分层（前因在上、尽量减少交叉）或按支线泳道；叙述顺序可按视角泳道或按章节分行。磁铁按钮开启吸附：拖动时对齐 10px 网格，并吸附到其他卡片的边与中线、显示参考线。多选后在选择工具栏「对齐」中左/中/右、顶/中/底对齐或水平/垂直等距分布。整理与对齐只改变位置，可在修改历史中撤销。
4. 在「正文写作」创建章节和场景，点击「生成当前场景」直接开始写：正文边生成边显示在编辑器上方，审阅后在右侧批准才写入。已有正文时点击「续写」，从光标处接着写（没有放光标时接在本场结尾）。单个场景的写作、续写和改写由程序直接安排，不再先经协调智能体规划。「更多场景操作」提供「完成本章空白场景」。
5. 手工修改正文自动保存。选中文字只记录选区，点击「改写选段」后先查看选段摘要、补充指令，再点击「开始改写」；在「阅读」检查完整作品。
6. AI 内容直接保存到作品，结果区可打开产出、查看记录和撤销。侧栏底部「创作记录」保留停止、重试、用量和修改历史；「设置」提供模型连接、作品备份恢复与 TXT 导出。重试已保存内容的失败任务前，会确认撤销该任务的修改。

「详情」与「AI 助手」是两个独立面板，默认关闭：宽于 1440px 时可并排停靠，选中节点不会挤掉 AI 助手；较窄窗口中 AI 助手为抽屉，1100px 以下详情也为抽屉，同一时间只打开一个抽屉。AI 助手按任务状态只显示一种视图：编写目标（Ctrl+Enter 开始）、运行进度、待审批候选（直接在面板内查看差异、批准或拒绝）以及上次任务结果；「偏好记忆」单独成页。抽屉打开后焦点进入面板，Tab / Shift+Tab 在面板内循环，Escape 关闭并返回触发控件；放大到并排面板时解除背景锁定。切换作品会清空 AI 任务草稿；普通导航和查看引用保留明确准备的任务目标。顶栏显示实际保存状态，保存失败时保留输入并阻止离开，修正后可继续。

AI 目标任务的分工：协调智能体只负责制定计划、出问题时调整计划和写总结。计划保存后由程序按依赖执行各个专长，把它们的修改组成一份候选，修改了正文的候选先经独立审查（连续性、读者、文风三方读完整正文，每条意见引用原句并标明「必须」或「建议」；有「必须」的意见时，写作者只替换被指出的段落自动修订一轮，再复审一次），再交作者批准。某个计划节点失败时，协调智能体可以调整计划（目标、范围与依赖都没变的已完成节点直接沿用结果）、询问作者或说明后结束；已完成部分的修改照常交作者批准，未完成的节点写在任务总结之后。

工作区标签支持左右方向键、Home / End；更多场景操作支持上下方向键、Home / End、Escape，点击外部或执行操作会收起。成功提示在悬停或键盘焦点停留时暂停消失，错误与可撤销提示保留到手动关闭或新提示替换。阅读进度在离开前保存，返回时恢复位置，切章或调整字号后重新计算。页面、抽屉、菜单和对话框采用短动效；系统设置减少动态效果时关闭 CSS 动画与画布定位动画。

每次创作任务先由独立的立意智能体分析主题问题、人物选择、选择代价与表达方式，结果保存到创作桌并供后续创作使用。轻小说、爽文和口水文学同样深化立意，同时保持作者选择的风格与娱乐性。立意可以手工修改，也可以单独运行「深化立意」。

大纲编排、正文生成与修订会自动跟进人物演进。人物页按世界事件展示视角、心理、动机和变化依据，并关联叙述场景；无正文时明确标为计划，已有正文优先于大纲。倒叙和重复叙述不会改变人物经历的世界顺序。

创作伙伴提供「人物演进」「世界因果」「叙述编排」「完善灵感」「深化立意」「一致性跟进」六类专项工具。创作桌、对象详情、图上多选与正文工具栏可直接选择相关工具与资料，点击开始执行。手工内容保存后提供「跟进本次修改」；移动节点、调整阅读偏好不会触发该提示。手工编辑不会自动发起外部模型请求。

## 创作伙伴：发散、追问与分层大纲

创作伙伴是与目标任务并行的轻量对话，不占用作品的任务位置。它在不同界面用不同方式唤出，并在指针或按钮旁弹出可拖动的对话框：

| 界面 | 唤出方式 | 伙伴做什么 | 采纳后写入 |
| --- | --- | --- | --- |
| 灵感画布 | 右键卡片「围绕它发散 / 如果它反过来？ / 反转它 / 追问我」；右键空白「在这里发散…」；选中后按 `I` 或选择工具栏「发散」 | What-if、反转、冲突升级、人物秘密等方向互异的点子，以及苏格拉底式追问 | 画布便笺，围绕锚点放射排布并连线，可一次放进新分组 |
| 世界因果 | 右键事件「推演后果 / 补一个前因 / 如果它没发生」；右键空白「这里还缺什么事件？」 | 前因后果推演 | 世界事件，自动接入因果链并保持因在果前 |
| 叙述顺序 | 右键或多选场景「诊断这一段的节奏 / 换个开篇 / 推迟这里的揭露」 | 节奏与信息揭露诊断，给出互斥的重构方案，附调整前后顺序对比 | 只重排场景、修改大纲或视角、插入空白场景，不改正文 |
| 大纲 | 情节规划 →「大纲」：节点上的「展开下一层 / 3 个版本 / 追问我」，左侧「一键生成全书草案」 | 梗概 → 幕/卷 → 章节 → 场景节拍逐层展开，可按三幕式、起承转合、英雄之旅、救猫咪、网文升级流、悬疑推理、感情线等模板 | 幕/卷、章节概要与空白场景；可勾选部分分支采纳，之后继续采纳其余部分不会重复创建 |
| 正文写作 | 工具栏「卡文了？」 | 几个可以直接写下去的下一拍 | 补进当前场景大纲，或放到画布 |

每轮回复包含简短回应、最多三个追问、点子或方案，以及可点击的后续追问。回答追问会在同一对话中继续，伙伴会承接之前的回答和已采纳内容。「稳妥 / 大胆 / 天马行空」控制偏离现有设定的幅度，选择会被记住。

采纳是一次带「采纳创作伙伴」标签的 AI 修改：主进程只读取已保存的建议并转换为领域命令，不接受界面传入的内容；不会删除任何内容，也不会改写已有正文。每次采纳都可以在对话中撤销，也会出现在修改历史中。正文生成与改写仍走目标任务，保留独立审查与作者审批。

全部对话保存在本机，可在 AI 助手的「对话」标签中查看、继续或删除；作品备份不包含对话。章节概要与所属幕/卷的作用会进入正文写作上下文，帮助写作智能体把握本章任务。

## 故事记忆：百万字长文

长篇不必每次把全书交给模型。叙境为作品维护分层的「故事记忆」，各个智能体按需逐层放大：

```
全书梗概 → 卷摘要 → 章摘要 → 场景摘要（事件、人物变化、新设定、伏笔） → 原文片段
```

- **零 token 索引**始终可用：正文按段落切块建立检索索引，并记录每个人物、地点、物件在哪些场景出现。出场按名称和「别名」（对象详情中填写的昵称、称谓）查找，同一位置优先匹配最长的名字，「李明」不会算进「李明月」。检索返回最相关的段落（每场最多两段），而不是整场正文。
- **模型摘要**在后台生成：正文保存后，作者停止编辑约 90 秒，就按阅读顺序把待整理场景分批交给模型，每批不超过约 1.2 万字；随后只重算输入发生变化的章、卷与全书汇总。超过 1.6 万字的场景分段整理后再合并，不省略中段。模型漏掉的场景不存兜底摘要，下次整理时重试。摘要只读取正文，不读大纲和作者设定。
- **伏笔账本**：每场摘要记录新出现的悬念、伏笔和承诺（并标出是否关系主线），以及本场回收了哪些。伏笔编号由开启它的场景和措辞决定，重新整理该场时沿用原编号，后文的回收记录不会错位；措辞相近的重复伏笔合并为一条。整理时，模型能看到主线伏笔和本批正文提到的早期伏笔，不只是最近的几十条。写作时列出尚未回收的条目：涉及本场人物的、主线的、近期仍被提起的排在前面，超过 30 章没被提起的次要伏笔排在最后。
- **语义索引（可选）**：在模型设置中填写「向量检索模型」（例如 `text-embedding-3-small`）后，整理故事记忆时会为每个段落计算向量并保存在本机，只重算改动过的段落。协调智能体检索原文时，除了字面匹配，也会找出意思相近的段落，即使它们没有共同的字词。不填写则只用字面检索，不产生额外请求。
- **失效判断**：摘要按正文 hash 判断是否过期。小幅修改时继续使用旧摘要，并标注它基于较早版本；改写幅度较大时，改用大纲和首尾句兜底，直到重新整理。

写作某一场时，模型收到的是：全书梗概、更早的卷摘要、最近 5 章的章摘要、本章前几场的摘要、未回收伏笔、本场人物上次出场的摘要与原文片段，以及紧接本场之前的约 6,000 字原文。在百万字作品的后期场景中，这些材料合计约一万字符，并始终保留紧邻的前文。

其他智能体也使用故事记忆：
- 读者审阅：只看到已读章节的章摘要，加上最近 1.2 万字原文；看不到卷和全书汇总，也看不到后文。
- 连续性审阅：直接检查候选实际改动的场景（整场正文，场景很多时平分约 1.8 万字的预算），以及这些场景涉及的人物和设定。
- 协调智能体与创作伙伴：目录以当前位置为中心，较远的章节只给骨架。协调智能体还可以调用 `read_story_memory`、`search_context`、`read_text`，逐层读取章节摘要、人物出场时间线和原文窗口。

「设置 → 故事记忆」显示已整理和待整理的场景数、本次启动以来的用量，可以切换自动或手动整理，也可以立即整理或停止整理。待整理内容超过约 6 万字时（例如导入整部旧作），自动模式不会自行开始，由作者点击「立即整理」；整理分批进行，停止后已完成的部分会保留。模型设置中的「摘要模型」可以填写更便宜的模型，留空则使用主模型。

故事记忆是辅助材料，不是正式事实，与原文冲突时以原文和设定为准。它保存在本机的 `workspaces.sqlite` 中，不改动作品，不产生修改历史，也不进入作品备份；恢复备份后会重新整理。

## 快捷键

- Ctrl+K 搜索与跳转（页面、场景、人物、AI 工具）；Ctrl+1…5 切换主要页面；Ctrl+J 开关 AI 助手；Ctrl+I 开关详情；Ctrl+\ 收起导航。
- Ctrl+S 立即保存全部修改（平时也会自动保存）。
- 正文写作中 Ctrl+Shift+F 进入专注模式，Esc 退出；Alt+↑ / Alt+↓ 切换到上一个 / 下一个场景（可跨章）。
- 章节目录中双击场景名或按 F2 重命名，Enter 确认，Esc 取消。新建场景后光标直接进入正文，新建章节后可直接输入章节名。
- 目录显示每章字数、全书字数及本次打开以来的增减；编辑器上方的 A− / A＋ 调整正文字号，选择会被记住。
- 阅读页中 ← / → 翻到上一章 / 下一章。

## 画布操作

- 画布占满内容区。左上浮动工具栏在当前视口中心创建节点（N），可搜索引用素材、适应视图（F）与显示小地图；右上「AI 整理」处理整个画布；选中内容后底部出现选择工具条（成组、移入分组、AI 动作、删除）。右键在指针处创建，双击空白创建便笺，左下「?」查看全部快捷键。
- Ctrl 多选，Shift 框选；「成组」或 Ctrl+G 将选择组织为分组。分组可以嵌套，拖动标题会带动全部后代。
- 节点中心拖入展开的分组即可归组；拖出后自动移出，也可在详情或选择工具栏修改归属。
- 选中分组后拖动边缘调整尺寸；折叠隐藏成员并保留外部关联。解散分组保留成员和绝对位置，嵌套成员提升到原父组。
- 引用卡片直接编辑真实对象或场景，卡片备注单独保存。AI 产出和上下文来源均可跳回真实内容。
- 引用节点实时显示对象描述、场景大纲与人物心理；作品简述和立意显示在画布的作品方向中。「在画布定位」打开已有引用，「添加到画布」才会建立新引用；引用详情可跳往对应世界事件和叙述场景。
- 导航、章节目录和右侧内容面板均可收起。单项和批量删除展示关联影响，批量删除作为一次修改保存，删除后可撤销。

## 模型配置

初始为明确标识的「演示模式」，不访问外部模型，便于离线体验整个流程。演示文本是固定示例，不代表真实 AI 生成。

在模型设置中切换到真实模式，填写 API 根路径、API Key 和模型名称。例如 Base URL 为 `https://api.openai.com/v1`，不要填写 `/responses`。模型必须支持流式 Responses、function calling 和严格 JSON Schema。推理强度可留空使用模型默认值；不支持的参数会直接报告错误。「摘要模型」可选，用于整理故事记忆；留空则使用主模型。填写后，整理请求不发送推理强度和输出上限参数。「按角色指定模型」也是可选的：同一服务下，可以让创作统筹、正文创作、各类审查等智能体角色分别使用不同模型，留空的角色使用主模型；这些请求沿用同样的推理强度和输出上限。修改角色模型后，未结束的任务需按原配置恢复或重新开始。

「单次输出上限」可选，推理也计入上限。留空时，设置了推理强度用 32000 tokens，否则用 16000；服务的上限更低时请在这里填写。正文写到上限会自动续写，结构化结果被截断时会要求精简重写，仍不够时任务暂停，调高上限后可以恢复。请求不在服务端保存，设置了推理强度时会请求加密的推理内容，以便多轮调用回传；没有加密内容的推理片段不会回传。

连接失败、限流（429）和服务端错误会在收到任何输出前自动退避重试。服务明确返回错误时，任务暂停并显示原因，恢复时直接重发这一轮，不需要确认费用；只有连接中断、结果不确定时才需要确认。任务因其他错误失败时，可以「从检查点重试」：已完成的步骤、产出和候选直接沿用，已批准的修改保留在作品中，只重做中断的部分。检查点已清理（只保留最近 3 条已结束任务）、软件更新改变了工具，或模型服务已更换时，重试会按原目标新建任务，不把旧会话发给新的服务。故事记忆整理会让路给正在进行的创作任务；某一批内容无法整理时只跳过这一批，下次整理再试。

调用仅使用 Responses，不自动回退 Chat Completions。连接检查由用户点击触发，会向已配置的模型发送一次请求。真实创作会把当前任务所需内容发送给该服务。

密钥使用 Windows 系统加密，只在主进程解密使用，不显示在任务记录和作品备份中。任务监视展示公开输出和工具活动，不展示模型隐藏思维链。停止会取消本地请求与后续操作，远端计费是否即时停止由供应商决定。

## 人物与世界

人物、环境和事件共享对象系统，可增加自定义类型和字段。人物的 `自我认知` 用于角色代入；作者掌握的秘密应放在世界事实或普通设定中，通过知识记录明确授予角色。

「人物与设定」按小说三要素分为人物、情节、环境与设定三栏，每栏提示缺口（例如还没出场的人物、没有世界规则的环境），并各有 AI 入口。场景除视角人物与世界事件外，还可以标注出场人物和发生地点；写正文时只带入本场绑定或在大纲、前文中提到的环境，环境不超过 6 个的作品才全部带入。创作伙伴和智能体可以像人物一样新建、丰富环境；结构诊断需要新增场景而大纲里还没有对应章节时，会在同一方案里新建章节，未指明章节的新场景会自动得到一个同名新章，撤销时一并撤销。

事件使用相对时间序号：同序号代表同时发生；因果来源必须更早。角色只能获得目标事件之前的明确知识和当前角色感知，不因为事件发生过而自动知晓。知识保存内容快照，误解、谎言和后来发生的事实变化不会自动改写旧记忆。

读者智能体只看叙述顺序中已经出现的正文；不会获得场景背后的世界事实或尚未出现的章节。

人物状态是一个世界事件结束后的快照。角色代入只取得严格更早事件中的状态，当前事件的变化由作者写作上下文单独提供。事件中明确获知的内容快照用于事件结束后的演进，不提前进入事件开始时的人物记忆。作者侧的正文论据不进入角色代入。一个场景同时包含后续事件时，早期人物演进不会读取该场景整段正文，而以当场观察及安全的场景资料推演。

## 数据与撤销

数据在 Electron 用户数据目录中（通常 `%APPDATA%\叙境`），不是源码目录。`workspaces.sqlite` 保存作品、操作和任务（每个任务的作品快照只存一份；已结束的任务只保留最近 3 个的快照，任务记录本身不删除）；`provider.json` 保存模型设置与加密密钥。

AI 和手工操作经过同一入口。AI 遇到内容修改会重新读取版本，更新已有节点时保留人工位置、尺寸及折叠状态。AI 任务撤销恢复卡片内容与成员关系，保留之后的人工布局；同一内容被后来编辑或撤销将破坏后续引用时，会报告冲突。重试沿用这项保护；选段正文已变化时，需要重新选择。

写作上下文引用相关资料、当时有效的世界事实和人物认知。前文按全书阅读顺序取最近约 6,000 字原文，更早的内容由故事记忆的分层摘要补足；未绑定事件的场景只提供人物初始认知。

关闭窗口会先保存编辑器正文并等待操作队列；保存失败或正文冲突时保持窗口打开，先处理草稿再退出。

作品备份是包含设定、大纲、正文和阅读配置的 JSON 快照，不包含模型凭据与运行日志。恢复会创建独立作品副本，不覆盖已有作品。TXT 按章节与场景阅读顺序导出正文。

## 提示词与基准评测

发给模型的提示词都在 `src/main/prompts/`，每个提示词的版本由文本计算，不需要手工维护；任务记录的每一步会写下所用提示词的版本（「步骤日志」底部）。协调智能体的工具版本由工具名与参数结构计算，只改提示词不会让暂停中的任务无法恢复。

`src/main/eval/` 是一个小型基准集：两部样例作品（民国悬疑、轻小说日常），各自带有人物不知道的秘密、作者确认的约束和文风设定，以及写作、角色代入、读者审阅五个任务。每个任务自动检查：

- **知识越界**：角色代入与读者拿到的上下文里不能有秘密和作者侧资料（零 token，`npm test` 每次都跑）；输出里不能出现泄露秘密的说法。
- **违反作者约束**：写作上下文必须带上作者约束；任何输出都不能出现违反约束的说法。
- **文风问题**：写作上下文必须带上禁用词；正文用本地文风统计对照作者范文，禁用词、AI 套话和人称不符直接判为未通过。
- **格式**：正文长度合理，不夹 JSON、标题或说明；结构化结果字段齐全。

基准任务目前覆盖写作、角色代入与读者审阅三个专长的提示词；协调、创作伙伴、故事记忆与文风学习的提示词由 `npm test` 中的模拟测试覆盖流程，尚未纳入基准。修改提示词前后各运行一次，比较通过率：

```bash
NOVEL_EVAL_MODEL=<模型名> NOVEL_EVAL_API_KEY=<API Key> npm run eval -- --repeat 3 --out artifacts/eval/before
# 修改 src/main/prompts/ 之后
NOVEL_EVAL_MODEL=<模型名> NOVEL_EVAL_API_KEY=<API Key> npm run eval -- --repeat 3 --baseline artifacts/eval/before/latest-live.json
```

`NOVEL_EVAL_BASE_URL`、`NOVEL_EVAL_REASONING_EFFORT`、`NOVEL_EVAL_MAX_OUTPUT_TOKENS` 可选。报告列出改动的提示词和通过率下降的检查；有下降、或上下文检查失败时退出码为 1，加 `--strict` 时任何检查未通过都返回 1。不设置模型与 API Key 时使用本地演示响应，只验证评测流程与上下文检查。检查是基于标记词与本地统计的确定性检查，能抓住明显的退步；没有命中不等于完全合规，细微的问题仍需人工阅读报告中的输出。
